# NESMA 功能点度量规则参考

基于 GB/T 42588-2023 (ISO/IEC 24570:2018 MOD) 和国内行业实践经验。

## 五种功能组件

### 数据功能

| 类型 | 代码 | 定义 | 判定要点 |
|------|------|------|----------|
| 内部逻辑文件 | ILF | 在应用边界内被维护的、用户可识别的逻辑相关数据或控制信息 | 本系统创建/更新/删除的数据存储，如数据库表、配置文件 |
| 外部接口文件 | EIF | 被应用引用但不被维护的、用户可识别的逻辑相关数据或控制信息 | 其他系统维护但被本系统读取的数据，如外部API返回的参考数据 |

### 事务功能

| 类型 | 代码 | 定义 | 判定要点 |
|------|------|------|----------|
| 外部输入 | EI | 处理来自边界外的数据或控制信息，目的是维护一个或多个ILF或改变系统行为 | 数据的增删改操作，如用户提交表单、批量导入数据 |
| 外部输出 | EO | 向边界外发送数据或控制信息，包含额外的处理逻辑（计算、派生数据等） | 含计算/统计/汇总逻辑的查询和报表，如数据分析报表 |
| 外部查询 | EQ | 向边界外发送数据或控制信息，不包含额外处理逻辑（直接检索呈现） | 无计算逻辑的数据查询，如列表查看、详情查看 |

## 功能点赋值表

### 预估法（早期 / 需求模糊阶段）

仅识别 ILF 和 EIF，使用固定权重：

```
FP(预估) = ILF数量 × 35 + EIF数量 × 15
```

### 估算法（需求中等明确）

识别全部 5 种功能，使用默认复杂度：

| 类别 | 默认复杂度 | 功能点数 |
|------|------------|----------|
| ILF | 中 | **10** |
| EIF | 中 | **7** |
| EI | 中 | **4** |
| EO | 中 | **5** |
| EQ | 中 | **4** |

此为"7/5/4/5/4"估算法（国内行业通用简化版，适用于需求中等明确阶段）。

### 详算法（需求完全明确）

根据 DET/RET/FTR 确定复杂度后查表：

| 复杂度 | ILF | EIF | EI | EO | EQ |
|--------|-----|-----|----|----|-----|
| 低 | 7 | 5 | 3 | 4 | 3 |
| 中 | 10 | 7 | 4 | 5 | 4 |
| 高 | 15 | 10 | 6 | 7 | 6 |

## 复用程度调整

| 复用程度 | 调整系数 | 说明 |
|----------|----------|------|
| 高 | 0.33 | 功能大部分可直接复用，少量改造 |
| 中 | 0.67 | 功能部分可复用，需一定改造 |
| 低 | 1.0 | 功能全新开发，无可复用基础 |

## 修改类型调整

| 修改类型 | 调整系数 | 说明 |
|----------|----------|------|
| 新增 | 1.0 | 全新开发功能 |
| 修改 | 0.5 ~ 1.0 | 基于现有功能改造（按实际比例） |
| 删除 | 0.0 | 废弃功能不计入 |

## 规模变更因子 (CF)

### 业务领域因子

| 业务领域 | 因子值 |
|----------|--------|
| 办公自动化系统 | 1.0 |
| 科学工程（算法、模拟、统计、大数据分析等） | 1.25 |
| 多媒体（图形、影像、地理信息系统等） | 1.3 |
| 智能信息（自然语言处理、人工智能、专家系统等） | 1.7 |
| 系统（操作系统、数据库系统、集成开发环境等） | 1.8 |
| 通信控制（通信协议、实时处理、安全定位系统等） | 1.9 |
| 过程控制（自动控制、嵌入式等） | 2.0 |

### 应用类型因子

| 应用类型 | 因子值 |
|----------|--------|
| 无分布式处理要求 | -1 |
| 通过客户端/服务器协作 | 0 |
| 需特殊技术保证多节点并行处理 | 1 |

### 质量特征因子

| 子因子 | 无特殊要求 | 有一定要求 | 严格要求 |
|--------|-----------|-----------|---------|
| 性能 | -1 | 0 | 1 |
| 可靠性 | -1 | 0 | 1 |
| 多站点 | -1 | 0 | 1 |

### 开发语言因子

| 语言/平台 | 因子值 |
|-----------|--------|
| C 等 | 1.5 |
| JAVA、C++、C# 等 | 1.0 |
| Python 等 | 0.8 |
| PowerBuilder、ASP 等 | 0.6 |

### 开发团队背景因子

| 团队背景 | 因子值 |
|----------|--------|
| 无同类项目经验 | 1.2 |
| 有同类项目经验 | 1.0 |
| 为本行业开发过类似应用 | 0.8 |

## 工作量计算公式

```
CF = 业务领域因子 × 应用类型因子 × (1 + 0.025 × Σ质量特征因子) × 开发语言因子 × 团队背景因子
S = AFP × CF
AE(人天) = S × PDR / 8
```

PDR（基准生产率）参考值：
- 智能信息类：10.48 人时/功能点
- 通用业务类：10.12 人时/功能点

## 常见功能归类示例

### ILF 示例
- 用户信息表、订单数据表、设备台账、专利数据库、知识库
- 系统配置参数、业务规则库

### EIF 示例
- 外部系统提供的组织机构信息
- 第三方API返回的行业标准数据
- 企业统一认证平台的用户认证接口

### EI 示例
- 用户注册/登录（维护用户ILF）
- 新增/编辑/删除设备信息
- 批量导入数据
- 提交审批

### EO 示例
- 统计分析报表（含汇总、排序、计算）
- 导出处理后的数据文件
- 风险评估报告
- 数据大屏展示（含实时计算）

### EQ 示例
- 按条件查询设备列表
- 查看用户详情
- 数据字典查询
- 日志查看

```json
{
  "project_name": "项目名称",
  "project_type": "新建项目",
  "project_info": {
    "business_domain": "智能信息",
    "app_type": "科学工程",
    "quality": {
      "分布式处理": "有一定要求",
      "性能": "有明确要求",
      "可靠性": "严格要求",
      "多站点": "无特殊要求"
    },
    "dev_language": "JAVA、C++、C#等同等语言/平台",
    "team_background": "为本行业开发过类似应用"
  },
  "method": "估算法",
  "functions": [
    {
      "level1": "一级功能模块",
      "level2": "二级功能模块",
      "name": "具体功能名称及说明",
      "category": "EI",
      "reuse": "高",
      "modify_type": "新增"
    }
  ]
}
```

`business_domain` 和 `app_type` 均从以下类别中选择：办公自动化系统 / 科学工程 / 多媒体 / 智能信息 / 系统 / 通信控制 / 过程控制

`quality` 各维度取值：无特殊要求 / 有一定要求（或有明确要求）/ 严格要求
